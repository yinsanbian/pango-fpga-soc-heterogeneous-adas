## 7. 关键设计与代码事实

| 项 | 内容 | 位置 |
|---|---|---|
| 捕获提交门 | `!bad_frame && !overflow && active_lines∈[1000,1088] && frame_cycles∈[2.0M,2.8M]` | `pg100_hdmi_capture` |
| bad_frame 来源 | 当前只由 `overflow` 置位；其余几何错误降级为 `bad_reason` 位 | 同上 |
| `overflow` 语义 | = `pixel_control_overflow` = **commit 元数据 FIFO(8 深) 溢出**（`commit_valid && !control_ready`），不是像素 FIFO 溢出 | `pg100_pixel_line_cdc` |
| `rate60` | `measured_edges > 400`（1 ms 窗口）：1080p60≈580，1080p30≈290 ⇒ 只判像素时钟档位，不判帧率 | 前端 |
| `frame_skip` | 60Hz 时按帧抽稀（隔帧抓），**不降低单帧像素率** | 捕获 |

## 8. 已确认结论

1. **解码器相位 = 0**：x=0..63 原始像素 64 位探针与编码器期望序列逐位相同。
2. **提交门按源帧率放行**：60Hz → 0 提交；30Hz → 有提交（PC 5.3/s；100Pro 捕获丢弃 11.7/s）。
3. **accepted 恒 0 与 export/身份无关**：export 打开后 accepted/rejected 仍全 0；`dropped=0` ⇒ commit 事件未到达 store。
4. **新构建 8/8 黑屏**：清空工程、分阶段构建、显式位宽、载荷交换均无效；唯一可用的是 GUI 构建 `23479887` 与旧交付 `seed2`。
5. **黑屏态特征**：有像素时钟、I2C 可写、`freq=0`、无 VS；属 RX 上电/配置边际，非位流"下错"。
6. **50K 无 HDMI 输出不成立**：50K 一直在收包出图；`FRM=0x33` 为源位图。
