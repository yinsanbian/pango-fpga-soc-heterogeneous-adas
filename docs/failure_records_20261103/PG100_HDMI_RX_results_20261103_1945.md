### A3. `pg100_hdmi_config` 的复位来源与时长

- `config_owner.rst_n = ctrl_rst_n`，来自 `pg100_board_reset`（`pg100_mainline_board_top.v:3516`、`:3482-3485`）。
- `pg100_board_reset` 在 `por_n` 释放后把 `shared_rst_n` 拉低 `HOLD_CYCLES=2,700,000` 个 clk27（27MHz，约 **100ms**），随后释放；`shared_rst_n` 直接输出到 `rstn_out`（G25），因此**每次 FPGA 配置都会给 MS7200/MS7210/PHY 一个约 100ms 的硬复位脉冲**。
- 没有单独的 RX RSTN 控制，也没有 HPD 控制。
- `ctrl_rst_n` 是 `shared_rst_n` 在 clk27 域的两级同步释放；`pixel_rst_n = (shared_rst_n && pixel_clock_good)` 在 pclk 域同步释放。
- 代码：`pg100_mainline_board_top.v:3730-3774`（board_reset），`:3819-3895`（hdmi_config）。

### A4. I2C ACK 检查、重试、读回

- I2C master 在每字节后检查 ACK：`success <= !failed && sda_sync[1] && (!clearing || recover_only);`（`pg100_mainline_board_top.v:4014`）。
- 配置 FSM 对每次事务检查 `success`：
  - 失败重试最多 `RETRY_LIMIT=3`，每次失败进入 `RECOVER`（总线恢复脉冲）后重试（`:3879-3887`）。
  - 仍失败则 `init_failed=1`、`failure_code=master_error`、`FINISH`（`:3883`）。
- 读回校验：只对 probe 阶段做 `reg 0x0003` 写 `0x5A` 再读回比较（`:3863-3866`、`:3874`）。**其余 360 条配置写入没有逐条读回校验。**
- probe：先对 0x2B、0x59 各做一次写/读（`probe_stage<4`），确认 I2C 通信。

### A5. `SETTLE_CYCLES=9,450,000` 的计时起点

- 在 `PREPARE` 中，若当前 ROM 条目 `entry[31]` 为 1 且 `wait_count==0`，装载 `SETTLE_CYCLES` 并进入 `SETTLE`；`SETTLE` 在 clk27 下倒数，到 1 后回 `PREPARE` 继续下一条（`:3867-3870`、`:3888-3889`）。
- 即：**在该条目对应的写事务完成后**才开始计时，而不是从配置完成/RSTN 释放开始。
- 9,450,000 / 27MHz = **350ms**。
- 当前 ROM 末尾 299–310 条目（`0x2b200301`、`0x2b209c00`…`0x2b021500`）的 bit31 均为 0，**没有触发 SETTLE**。

### A6. 与官方 `2_10_hdmi_loop` 的差异（关键）

官方 `source/ms7200_ctl.v` 的流程（已从 `D:/pg100pro/盘古100Pro+开发板（MES2L676-100HP）配套资料/2_Demo/2_10_hdmi_loop.rar` 解出核对）：

1. `CONECT`：写 `0x0003=0x5A` 并读回比较；
2. `INIT`：顺序写 300 条寄存器（索引 0–299）；
3. `WAIT`：`delay_cnt == 24'h989680` = **10,000,000 个时钟**（50MHz 下 200ms）；
4. `STA_RD`：**读** `0x209C、0x209D、0x209E、0x209F` 四个字节组成 `freq_rec`，并检查 `freq_rec[17:16]` 的 `00 → 10` 变化（`freq_ensure`）；**只有频率有效才进入 SETING**；
5. `SETING`：写 7 条“使能”序列：
   `0x1010=0x01, 0x1024=0x00, 0x0200=0x00, 0x1024=0x70, 0x0200=0x07, 0x0215=0x01, 0x0215=0x00`；
6. `init_over`。

我们的旧流程（19:26 之前）：

1. probe 0x2B/0x59；
2. 顺序写 ROM 的 360 条，其中 **0x209C–0x209F 被当成“写 0”**（`hdmi_config_rom.vh` 索引 300–303 为 `2b209c00`…`2b209f00`）；
3. **没有 200ms 等待、没有读频率、没有 freq_ensure**；
4. 紧接着写 0x1010/0x1024/0x0200/0x0215 使能（索引 304–310）；
5. 继续写 MS7210 的配置（索引 311–359）。

差异结论：**旧流程在“输入频率尚未被 RX 测到/有效”时就执行了使能序列**，这与“随机锁不上”高度吻合（H2 类：配置不完整/时序竞争）。

### A7. `pg100_board_reset`

- `HOLD_CYCLES=2,700,000`（100ms）、`WINDOW_CYCLES=27,000`（1ms）、`MIN_EDGES=270、MAX_EDGES=630`。
- `pixel_clock_good`：每 1ms 统计 `pclk/256` 的边沿数（`phb` 每 256 个 pclk 翻转一次），在 [270,630] 内连续 3 个窗口后才置 1；任一窗口失败立刻清 0 并累加 `clock_loss_count`。
- `pixel_rst_n = (shared_rst_n && pixel_clock_good)` 在 pclk 域两级同步；因此 `pixel_rst_n=0` 的条件是：`shared_rst_n=0`（配置后 100ms 内）或 `pixel_clock_good=0`（pclk 边沿数不在窗口内）。
- `video_ready`（状态字 w2 bit3）= `pixel_clock_good && hdmi_init_done` 经 native_clk 两级同步。

### A8. 直通路径是否被 capture 门控

- `pg100_rgb_tx` 只依赖 `rx_pclk`、`pixel_rst_n`、`enable = tx_active && ready_rgb`（`pg100_mainline_board_top.v:3540-3542`）。
- `tx_active` 在 `ready_rgb` 有效后由 `rx_vs` 上升沿置 1（`:3494-3502`）。
- capture 模块的异常不会直接门控直通；但两者共享 `pixel_rst_n`、`ready_rgb`、`rx_pclk`。若 `pixel_rst_n=0` 或 `ready_rgb=0`，直通和采集会同时停。

### A10. 提交判据的时钟域与采样时刻

- 全部在 **pclk 域**的同一个 `always @(posedge pclk or negedge rst_n)` 内（`:3580-3660`）。
- `frame_cycles`、`active_lines` 是 pclk 域寄存器；`frame_cycles` 在每帧内逐 pclk 递增、在 vrise 清零/锁存；`active_lines` 在 DE 结束时递增、在 vrise 清零。
- 提交条件在 vrise 当拍用“当前寄存器值”判断：`!bad_frame && !overflow && !de_in && !de_d && active_lines∈[HEIGHT-2,HEIGHT+8] && frame_cycles∈[2,400,000,2,600,000]`（`:3605-3614`）。
- `commit_reason`（w37[15:12]）也在同一拍锁存：bit0=`de_in||de_d`，bit1=行数窗口失败，bit2=帧长窗口失败。

### A11. w37 各信号的来源/域

| 位 | 信号 | 来源 | 时钟域 |
|---|---|---|---|
| 0 | `pixel_rst_n` | `pg100_board_reset` | pclk 同步释放 |
| 1 | `ready_rgb` | frontend：`config_sync[2] && format_sync[2]`，均同步到 pclk | pclk |
| 2 | `bad_frame` | capture 内部寄存器 | pclk |
| 3 | `pixel_control_overflow` | 存储/CDC 溢出 | 由存储侧产生后送 pclk（具体 CDC 见存储模块） |

这些位与 w32–w39 一样，是 **pclk 域寄存器直接接到 native 域快照总线**，没有逐位同步；在 native_clk 采样时可能有亚稳态/撕裂（现有诊断版 WNS<0 也与此有关）。

## 3. 本次实验：按官方流程加入 freq_ensure

### 3.1 改动（单变量：配置流程）

在 `pg100_hdmi_config` 中：

- 新增状态 `FREQ_WAIT / FREQ_RD / FREQ_GAP`，`state` 扩为 4 位。
- 写完 index 299 后：等待 `SETTLE_CYCLES=9,450,000`（350ms）→ 读 `0x209E` → 若 `read_value[1:0]==2'b10` 则跳到 index 304（执行使能+MS7210），否则每 100ms 重试。
- 增加 100 次重试上限（约 10s），超时后**强制**跳到 index 304（保留旧行为兜底），并置 `dbg_freq_forced=1`。
- 新增遥测：`dbg_freq_value`（0x209E 读回）、`dbg_freq_tries`、`dbg_freq_state`、`dbg_freq_forced`，映射到 PGS2：
  - w29 = `{24'b0, dbg_freq_value}`
  - w30 = `{16'b0, dbg_freq_tries}`
  - w31 = `{27'b0, hdmi_init_failed, dbg_freq_state}`

### 3.2 实测结果（19:41 烧写，19:42 读取，连续 8 次一致）

```
state(w2) = 0x087f           // ddr_init=1, cpd_lock=1, hdmi_config=1, video_ready=1,
                             // link_gigabit=1, rgb_confirmed=1, run=1
w29 freq_value = 0x00        // 0x209E 读回 0x00
w30 freq_tries = 99          // 达到强制阈值
w31 freq_state = 0x5         // FINISH；hdmi_init_failed=0
w36 vs_cap = 0
w34 captured = 0
w33 active_lines = 0
w38 good_identity = 0
w39 bad_identity = 0
w37 = 0x00000003             // ready_rgb=1, pixel_rst_n=1, bad_frame=0, overflow=0
```

结论：

1. freq 读取机制本身工作（能读回 0x209E），但 RX 报告 **0x209E=0x00**，即 **未测到有效输入频率**。
2. 强制使能后 RX 仍未锁定：`vs_cap=0`、无采集、直通无有效数据。
3. `pixel_clock_good=1`（video_ready=1）与 `0x209E=0` 同时存在，说明 pclk 可能是 RX 自由运行时钟，而不是有效 TMDS 数据时钟。
4. 这与“100Pro HDMI IN 侧没有有效 TMDS”一致，而不是 capture/解码逻辑的问题。

### 3.3 与假设的对照

| 假设 | 判定 | 证据 |
|---|---|---|
| H1（FPGA 重配置时 MS7200 未复位，I2C 重写导致随机） | **部分不支持** | G25 在每次配置后被拉低约 100ms（A3），RX 确实被复位 |

## 4. 建议的下一步（按优先级）

1. **物理隔离（最高优先）**：用 PC 的 HDMI OUT 直接接 100Pro HDMI IN，采集卡接 100Pro OUT。
   - 若 `0x209E` 变成非 0（例如 0x02）且 `vs_cap>0` → 100Pro RX 与配置流程正常，问题在 50K→100Pro 的线/口/源。
   - 若仍为 0 → 100Pro HDMI IN 口或 MS7200 硬件/复位问题。
2. **若 PC 源正常**：换一根已知良好的 HDMI 线，重做 50K→100Pro；再测 `0x209E`、`vs_cap`。
3. **Phase C 观测增强**：在 clk27 域增加 `de_rise_cnt / hs_rise_cnt / de_high_samples`（1s 窗口），确认 RX 是否真的输出 DE；这能最终区分“RX 没出数据”与“FPGA 没接住”。
4. **Phase B 对照实验**：等物理链路确认后，用 08:25 等已知好位流（目前缺失，需要重建或找回）与当前位流各重烧 ≥10 次，统计成败；否则无法量化 H1/H3。
5. **时序干净化**：当前诊断版 WNS=-468ps/TNS=-15ns；在结论前应做一版去掉调试 CDC 的干净位流（All Constraints Met），再复测。
