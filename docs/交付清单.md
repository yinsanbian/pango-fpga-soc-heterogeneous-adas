## 工作流程规范（长期约束，不是建议）

**N1 证据优先，不做结论**

任何"完成/通过/更快"都要附命令与输出原文；没跑过的写"未验"，不写推测。没做到的单独列一节，不混进结论。

**N2 unavailable 三原则**

缺数据一律显示 `— unavailable(原因码)`；不显示 0 冒充测量值；不冻结旧值；回放/合成不得标成在线。原因码只来自协议公共头，界面不自己编。

**N3 单一实现，脚本生成**

字段只有 JSON 一份定义；字段文档、测试向量、本清单全部由脚本生成，禁止手写第二份。界面不复制推理逻辑。

**N4 冻结参数不擅自改**

方案里冻结的值（α=0.35/β=0.05、死区 2 px、max_hold 5、Q 格式）只报实测现象与代价，改动必须登记为偏离并写明理由。

**N5 源码与产物分家**

dashboard/data/**、reports/**、__pycache__ 都是产物，可随时由命令重建，不参与评审；产物只提供生成命令。

**N6 测试自跑、退出码即结论**

本机无 pytest：测试是纯 assert 脚本，`python xxx_test.py` 退出码非 0 即失败；每个测试文件自带中文用例名，失败信息要能直接定位断言。

**N7 跨平台纪律**

所有生成文件用 `newline="\n"`（否则 Windows 的 CRLF 会让两平台 sha256 不一致）；脚本用 `-X utf8`；不硬编码盘符与字体路径；Linux 字体按候选列表发现，找不到明确报错。

**N8 目录与命名**

板端部署预留 `rk_deploy/`；既有 `rk3566_deploy/` 不得改名或误标为 rk3568（RKD-04）。任务编号沿用子方案 RKD-xx，验收映射到 SAT-xxx。

**N9 偏离必须登记**

凡与方案原文不一致，写进 `docs/interface_contract.md` 的 D 编号：改了什么、为什么、代价是什么、如何回退。只写"是什么"不算登记。

**N10 提交前检查清单**

① 15 个测试文件全绿；② 重新生成字段文档/向量/清单；③ 截图重出且肉眼检查；④ 数字与文档一致（帧数/条数/百分比）；⑤ 新增字段同步改向量与测试夹具。

**N11 失败与坑要留档**

踩过的坑写进 README/证据文档的"已知边界"，例如：process() 会就地画叠加层导致缩略图带旧标注；payload_length 上限导致 ROADTHUMB 必须 JPEG。

**N12 门禁优先于画面**

LIVE/验收类标签只由证据决定：门禁未过就打印 BLOCKED 并非零退出，绝不因为"画面能出"就标 LIVE。合成/补位模式在 UI 上必须常驻标注。
