# 「夜瞳多目」严格对齐项目概述的上板方案

> 版本：v1.0  
> 目标器件：紫光同创 PGL50H-6IFBG484（盘古 50）  
> 原则：项目概述是功能约束；技术参考和工作区既有文档是候选依据，必须经过核验后才能进入 RTL 或答辩材料。

## 1. 先锁定边界

### 1.1 本方案必须实现的四条链路

1. 夜间/逆光增强：MSR 类光照归一化 + CLAHE 局部对比度增强。
2. 多车牌检测：单类轻量 YOLO 检测 + 硬件解码 + 多目标 NMS。
3. 车牌识别：LPRNet + 轻量化 CBAM；识别网络在 FPGA 逻辑中运行。
4. 软硬协同：RISC-V 只做调度、寄存器配置、CTC 后处理和 HDMI 字幕数据准备，不做卷积推理。

字符二值化与投影另设为检测框之后的旁路流水线，用于车牌带有效性检查、字符候选分割和答辩展示；LPRNet 主路径仍采用其论文中的无预分割识别方式。这样既实现项目概述要求的“字符分割流水线”，又不破坏 LPRNet 的理论前提。

### 1.2 对已有草案的纠偏

- `yolo裁切方案` 可作为检测器的算力和量化依据，但不能替换项目概述中的 LPRNet+CBAM 识别器。
- “180 个候选框/秒”不是 YOLO 原始候选框吞吐量。以 320×192、3 个检测尺度估算，原始网格约为 `40×24+20×12+10×6=1260` 个位置/帧，即 30 fps 时约 37,800 个位置/秒；经过置信度阈值和 Top-K 后再进入 NMS。
- 88.33%→95.00% 只能作为待复现实验的参考，不能在没有同数据集、同训练划分和同硬件定点结果时写成项目已达成指标。
- 端到端“小于 10 ms”、DDR3“实测超过 20 Gbps”、APM 的“INT8 双乘法打包”均必须板上实测后再写入答辩材料。

## 2. 最终数据流

```text
HDMI IN / DVP 摄像头
        │
        ▼
视频时序恢复 ── 异步 FIFO ── DDR3 原始帧乒乓缓存
        │                         │
        │                         └── 原始帧供 ROI 裁剪和 HDMI 回显
        ▼
RGB/YUV → 8 bit Y → 320×192 缩放
        ▼
MSR-lite（多尺度高斯 + log LUT）→ CLAHE（8×6 tile）
        ▼
INT8 单类 YOLOv8-nano 硬件推理
        ▼
检测头解码 → 置信度阈值 → Top-K(64) → 8 路无除法 NMS
        ▼
最多 6 个车牌框
        │
        ├── 二值化 → 行/列投影 → 字符候选分割/质量检查
        │
        └── DDR3 ROI 裁剪 → 94×24 缩放 → LPRNet+CBAM INT8
                                      ▼
                            CTC 贪心解码 / 结果队列
                                      ▼
RISC-V 取结果并生成字幕数据 → 硬件 OSD 叠加框、车牌号、置信度 → HDMI OUT
```

### 2.1 板卡和接口假设

以 PGL50H-6IFBG484 版本的盘古 50 为基线：42,800 LUT5、64,200 FF、134 个 18-Kbit DRM、84 个 APM；核心板使用两颗 DDR3 组成 32-bit 存储接口，理论峰值带宽约 25.6 Gbps。盘古 50 扩展板提供 HDMI 输入和 HDMI 输出；若手头型号只有摄像头接口，只需替换最前面的采集适配器，后面的 AXI-Stream 数据格式不变。

工程默认输入为 1280×720@30 Hz，AI 支路使用 320×192 灰度图。1080P 只作为后续扩展模式，不作为第一版闭环的前置条件。

## 3. 时钟、接口和存储组织

### 3.1 时钟域

| 时钟域 | 初始目标 | 作用 |
|---|---:|---|
| `pix_clk` | 由 HDMI/DVP 输入恢复 | 采集、行场计数、输入 FIFO |
| `video_clk` | 按 HDMI 输出制式 | 帧读出、OSD、HDMI TX |
| `ai_clk` | 先以 150 MHz 收敛，200 MHz 为冲刺目标 | CNN、CBAM、NMS、缩放 |
| `cpu_clk` | 50–100 MHz | PicoRV32、寄存器和中断 |
| `ddr_clk` | 按 HMEMC/DDR3 控制器例程 | DDR3 控制器和 AXI4 主端 |

所有跨域通道使用异步 FIFO；不要用组合逻辑直接跨时钟。每个时钟、PLL 生成时钟、输入恢复时钟和异步时钟组都写入约束文件后再综合。

### 3.2 AXI 约定

- 图像与特征数据：AXI4-Stream，`tdata` 采用 8 个 INT8 像素/特征打包，保留 `tvalid/tready` 背压。
- `tuser[0]`：帧首；`tlast`：行尾；另用 sideband 或寄存器传递宽、高、帧号。
- 参数和状态：AXI4-Lite 寄存器空间；若 PDS 工程中的软核不是 AXI 主端，则加一层 native-to-AXI-Lite bridge。
- DDR3：优先使用 PGL50H HMEMC 的 AXI4 端口；CNN DMA 使用长 burst，视频读写使用独立通道或仲裁优先级。

### 3.3 DDR3 区域

物理基地址由 PDS 工程最终分配，软件只使用链接脚本导出的符号，不在 RTL 中写死下列数值。

| 逻辑区域 | 内容 | 访问者 |
|---|---|---|
| `FRAME_A/B` | 原始帧或 YUV 帧乒乓缓存 | 视频 DMA、ROI 裁剪、OSD |
| `WEIGHT_DET` | 裁切后 YOLO 权重和量化参数 | CNN DMA |
| `WEIGHT_LPR` | LPRNet+CBAM 权重 | CNN DMA |
| `ACT_PING/PONG` | 大于片上 RAM 的层间特征图 | CNN DMA |
| `CLAHE_TILE` | 当前/下一 tile 的直方图和映射表 | CLAHE |
| `RESULT` | 6 个检测框、6 个识别结果、性能计数器 | NMS、RISC-V、OSD |
| `FONT` | 5×7 或 8×16 字库 | RISC-V/OSD |

片上 DRM 只放行缓存、窗口缓存、tile 直方图、短 FIFO 和当前层 tile；不能假设整套网络权重或整帧中间特征图放得进片上 RAM。

## 4. 模块一：MSR-lite + CLAHE 夜间增强

### 4.1 定点算法

在亮度通道 Y 上实现：

```text
R(p) = Σ w_s × [ log(Y(p)+1) - log(G_sigma_s * Y(p)+1) ]
Y_msr = clamp(alpha × R + beta)
Y_out = CLAHE(Y_msr)
```

建议三尺度先固定为 `sigma = 3, 9, 15` 的可分离近似核，`w_s=1/3`；所有系数、增益和偏置由 RISC-V 寄存器配置。对数用 256 项 `log2` LUT，内部使用 Q4.12，最终饱和到 8 bit。第一版不做 RGB 三通道 MSR，避免将三倍的行缓存、LUT 和带宽引入闭环。

### 4.2 RTL 结构

1. `rgb2y`：乘法系数用移位加法或小 LUT 实现，避免占用 APM。
2. `gauss_h/v_0/1/2`：每个尺度使用行缓存 + 移位寄存器；横向和纵向卷积分开流水。
3. `log_lut`：输入和模糊结果各查一次 LUT。
4. `msr_mix`：三尺度相加、增益偏置、饱和和帧统计。
5. `clahe_hist`：8×6 tile，256 bin，clip limit 可配置；直方图使用双 bank，当前 tile 统计时准备下一 tile。
6. `clahe_cdf`：clip 后分配超出量，生成 CDF 映射表。
7. `clahe_interp`：取相邻 tile 的四个映射结果做双线性插值。

CLAHE 不是严格的单次像素即出算法，必须允许 tile 统计和映射的内部两阶段过程；对外仍封装成带帧首/帧尾的流式模块。若第一阶段时间不够，保底是同一接口下的全局 HE，不能改变后级输入格式。

### 4.3 验收

- Python 参考模型、RTL 仿真和板上输出对同一帧逐像素比对；先允许 1 LSB 量化误差，再逐步收紧。
- 夜间、逆光、车灯炫光三组数据分别计算平均亮度、局部对比度、PSNR/SSIM；PSNR/SSIM 只对有参考图像的数据计算。
- 记录 `enhance_cycles`、tile stall、丢帧数；不能只给主观截图。

## 5. 模块二：单类 YOLOv8-nano、解码和多目标 NMS

### 5.1 训练与导出约束

检测任务只保留一个类别 `license_plate`，输入固定为 320×192。训练时执行以下结构化改造并重新训练，不能只在推理端删除通道：

- 单类检测头；
- 主要 3×3 卷积改为深度可分离卷积，首层和必要的跨通道融合层保留普通卷积；
- L1/L2 范数的结构化通道剪枝，初始剪枝率 30%，每轮剪枝后微调；
- INT8 QAT；
- BN folding；
- SiLU 改为硬件可实现的 Hard-Swish 或 ReLU6；
- YOLOv8 检测头的 DFL `reg_max` 先取 4，导出脚本和 RTL 使用完全相同的解码公式。

剪枝率、输入尺寸和 `reg_max` 都属于可测参数。若夜间小车牌召回率下降超过 3 个百分点，先恢复输入到 320×320 或降低剪枝率，不要直接增加 FPGA 逻辑。

### 5.2 CNN 加速器

采用共享的 INT8 卷积引擎，支持普通卷积、深度可分离卷积、1×1 卷积、ReLU6/Hard-Swish、加法残差、池化和重排。每层用 descriptor 描述 `H/W/Cin/Cout/stride/padding/weight_addr/scale/zero_point`，RISC-V 只写 descriptor 起始地址和启动位，真正的 MAC、激活和 DMA 由硬件完成。

采用输出通道 tile 和空间 tile：

```text
DDR3 weight burst → weight buffer
DDR3/AXI-Stream activation → line/tile buffer
                 → PE array → requant/activation
                 → next tile 或 ACT_PING/PONG
```

每层必须支持饱和、四舍五入和 per-channel scale；否则软件模型与 RTL 的误差会在深层累积。

### 5.3 检测头和无除法 NMS

检测头依次完成：

1. Hard-Sigmoid/指数等非线性使用 LUT；
2. DFL4 得到左右上下距离；
3. 还原到 320×192 坐标；
4. 类别分数与置信度相乘；
5. 低于阈值的候选直接丢弃；
6. 维护每帧 Top-K=64；
7. 8 路并行比较和 NMS，最多输出 6 框。

IoU 不使用除法：

```text
inter_area / union_area > threshold
⇔ inter_area × 2^Q > threshold_Q × union_area
```

坐标和面积用无符号定点；仿真时同时输出真实除法 IoU，检查比较边界。NMS 的比较对象是 Top-K 候选，不是仅有 4–6 个最终车牌；这样才能覆盖多车牌和密集误检场景。

### 5.4 验收

- 固定量化模型在 PC 上导出检测头中间张量；RTL 逐层比对，卷积、激活、DFL、NMS 分开定位误差。
- NMS 用随机框、完全重合框、包含框、边界框和密集车牌框做穷举测试；输出顺序和 Python golden 结果一致。
- 以“720P HDMI 显示 30 fps、检测框最多 6 个、检测结果不回写 DDR 冲突”为必达；AI 更新帧率和端到端延迟以板上计数器实测为准。

## 6. 模块三：LPRNet + CBAM 识别

### 6.1 ROI 和识别器

每个 NMS 框映射回原始帧，裁剪并缩放为 `94×24×1` 灰度 ROI。最多建立 6 个 ROI 描述符，通过同一 CNN PE 阵列轮询执行。检测器输出新结果前，HDMI 可以继续显示上一帧有效车牌号，避免识别队列阻塞视频输出。

LPRNet 使用 CTC 输出字符序列，字符表、blank 索引和最大序列长度放在参数区。CTC 贪心去重和去 blank 可以放在 RISC-V 上，因为它是结果后处理，不是神经网络推理；若 CPU 负担过高，再将 argmax/collapse 下沉为一个小型 RTL 解码器。

### 6.2 CBAM-lite 硬件位置

CBAM 只放在 LPRNet 最后一个较小的特征图上，先做单个模块验证，再决定是否复制到倒数第二个 block。这样符合项目的“嵌入注意力机制”要求，同时不把 7×7 空间卷积复制到所有层。

- 通道注意力：全局平均池化 → `C/r` 中间层 → ReLU → `C` 输出 → sigmoid LUT → 逐通道乘法。`r=8` 起步。
- 空间注意力：通道平均池化与最大池化并行 → 2 通道 → 7×7 卷积 → sigmoid LUT → 逐元素乘法。
- 7×7 卷积用 7 行缓存和 7 级移位寄存器；乘法器与卷积 PE 时分复用，不能静态再复制一套大阵列。
- 注意力图使用 Q0.8，特征图使用 INT8；乘积在更宽位宽累加后右移并饱和。

项目概述里的“全局平均池化+两层 FC”对应上述轻量化通道分支；原始 CBAM 论文同时讨论平均池化和最大池化的通道分支。若采用平均池化-only 版本，训练、对照实验和论文描述必须明确写成 `CBAM-lite`，不要把它冒充为原始 CBAM 的逐字复现。

### 6.3 字符分割旁路

对每个 94×24 ROI 并行执行：

```text
8 bit Y → 固定/自适应阈值 → 1 bit
         ├── row_sum[24]：车牌带有效性和上下边界
         └── col_sum[94]：字符候选切分和字符数量估计
```

累加器只需加法器和 FIFO，100 MHz 下远高于 6 框/帧的吞吐需求。该旁路用于展示和异常样本诊断，LPRNet 主路径不依赖人工字符框，也不把分割误差传给 CTC。

### 6.4 验收

- 先在 FP32 PC 模型上完成“无 CBAM / CBAM-lite”的同训练集、同测试集消融；报告整牌准确率、单字符准确率和夜间子集准确率。
- 再做 INT8 QAT；板上识别结果与量化 PC 模型逐 ROI 比对，目标是整牌准确率损失不超过 2 个百分点，最终值以实际数据为准。
- 记录每个 ROI 的排队时间、推理周期、CTC 输出和置信度；不能只统计检测 FPS。

## 7. 模块四：RISC-V 软核、OSD 和控制寄存器

### 7.1 软核选择

默认使用开源 PicoRV32 的 `picorv32_axi`，配置 RV32IMC、AXI4-Lite 主端和中断；若板卡资料中的官方 RISC-V IP 已经有完整启动例程，可替换 CPU，但寄存器定义和软件职责不变。

### 7.2 软件职责

- 上电初始化：DMA、阈值、量化参数地址、帧缓冲地址、字体地址；
- 调度：启动/停止增强、检测和识别，处理 frame-done、nms-done、lpr-done 中断；
- 后处理：读取最多 6 个框和 logits，完成 CTC 贪心解码、结果超时和旧结果保持；
- 字幕数据：将 Unicode/中文省份字库映射为字库索引，写入 OSD result RAM；
- 诊断：读取模块周期、DMA 字节数、FIFO 水位、丢帧数和错误码。

CPU 不执行卷积、池化、CBAM、DFL 或 IoU；这些属于硬件数据面。

### 7.3 建议寄存器

| 偏移 | 名称 | 作用 |
|---:|---|---|
| `0x00` | `CTRL` | 全局使能、软复位、增强模式 |
| `0x04` | `STATUS` | busy、frame_done、nms_done、lpr_done、error |
| `0x08` | `FRAME_CFG` | 输入宽高、帧号、stride |
| `0x0C` | `ENH_CFG` | MSR 增益、CLAHE clip、tile 配置 |
| `0x10` | `DET_CFG` | score/NMS 阈值、Top-K、最大输出框数 |
| `0x14` | `DMA_BASE` | 帧、权重、激活和结果区的符号地址 |
| `0x18` | `IRQ_EN` | 中断使能 |
| `0x20–0x7C` | `PERF_*` | 各阶段周期、DMA 字节、丢帧计数 |
| `0x100+` | `RESULT_RAM` | 6 个框、6 个文本索引和置信度 |

## 8. 资源预算和收敛策略

这是设计预算，不是综合结果；每次 PDS 综合都要回填实际值。

| 资源 | 初始预算 | 处理策略 |
|---|---:|---|
| APM | CNN 56 + CBAM/缩放 8，保留约 20 | 共享 PE、时分复用；禁止未经测量的双乘法假设 |
| DRM | 不超过 100/134 | 只放 tile/line/FIFO；大权重和激活走 DDR3 |
| LUT5 | 不超过约 34k/42.8k | 激活/exp/log 用 LUT，避免大除法器和动态数组 |
| FF | 不超过约 50k/64.2k | 每一级流水寄存，过长控制状态拆分 |
| DDR3 | 视频 + 权重 + 激活合计留出余量 | 先做带宽测试，再固定 burst 和仲裁策略 |

第一个时序目标是 `ai_clk=150 MHz`；只有在 150 MHz 全链路无违例后，才尝试 200 MHz。若资源超标，按以下顺序降级：CBAM 只保留最后一层 → 检测器剪枝率从 30% 提到 40% 并重新 QAT → 检测输入 320×192 保持不变但降低 detector 更新频率；不删除四个功能模块。

## 11. 最终验收门槛

1. 视频：720P@30 HDMI 输入、叠加输出连续运行 10 分钟，无明显撕裂、死锁和 FIFO 溢出。
2. 增强：MSR-lite、CLAHE 都有 RTL 仿真和板上结果，固定测试帧误差在预先定义的定点容差内。
3. 检测：单类车牌、多车牌、4–6 框输出；NMS 对 golden 的保留/抑制结果一致。
4. 识别：LPRNet+CBAM 在板上输出完整车牌字符串；报告 FP32、INT8、CBAM 前后三组结果。
5. 软硬协同：RISC-V 可以通过寄存器改变阈值、启动链路、读取性能计数器并更新字幕；CPU 运行期间没有卷积循环。
6. 工程：每个模块都有 Python/RTL golden、单元仿真、PDS 综合资源报告和板上计数器；所有性能数字注明“理论、仿真或实测”。
