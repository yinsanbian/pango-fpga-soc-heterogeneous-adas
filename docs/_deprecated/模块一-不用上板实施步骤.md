# 模块一：不用上板的详细实施步骤

## 1. 本阶段目标

本阶段只完成四件事：

1. 在 PC 上复现 MSR-lite + CLAHE 的算法链路；
2. 明确定点规则，生成后续 Verilog 必须匹配的 golden reference；
3. 确定 320×192、8 bit Y 输入输出接口；
4. 用夜间、逆光和车灯炫光数据完成参数筛选与指标记录。

本阶段不做摄像头、HDMI、DDR3、PDS、RISC-V 或 FPGA 下载。

## 2. 依据和为什么这样实现

### 2.1 MSR

MSR 源自 Retinex 的光照/反射分解思想，用多个尺度的高斯环绕滤波估计光照，再进行对数域差分。理论依据是 Jobson 等人的 *A Multiscale Retinex for Bridging the Gap Between Color Images and the Human Observation of Scenes*；PC 参考可对照 [`muggledy/retinex`](https://github.com/muggledy/retinex)。

为了能迁移到 FPGA，本项目只在亮度 Y 通道上做三尺度 MSR-lite，不直接做 RGB 三通道 MSR：这样算法仍保留多尺度光照补偿，但行缓存、对数 LUT 和带宽约为单通道路径。

### 2.2 CLAHE

CLAHE 依据 Zuiderveld 的 *Contrast Limited Adaptive Histogram Equalization*：分 tile 统计直方图、限制 clip、计算 CDF 映射，再对相邻 tile 的结果做双线性插值，避免普通分块均衡的方格效应。

## 5. 固定第一版参数

配置文件为 `module1_enhancement/configs/default.json`：

| 参数 | 第一版值 | 原因 |
|---|---:|---|
| AI 图像尺寸 | 320×192 | 与项目上板方案的 AI 支路一致 |
| MSR sigma | 3、9、15 | 覆盖局部、中尺度和较大范围光照 |
| MSR 权重 | 1/3、1/3、1/3 | 先保持可解释和易定点 |
| log LUT | 256 项、Q12 | 8 bit 输入直接索引，后续可写进 ROM |
| CLAHE tile | 8×6 | 320×192 可整齐划分为约 40×32 tile |
| CLAHE bins | 256 | 与 8 bit 像素一一对应 |
| clip limit | 2.0 | 初始值，必须用数据调参 |

第一版只允许调 `retinex_gain`、`retinex_bias` 和 `clahe_clip_limit`。不要同时修改尺寸、sigma、权重和 clip，否则无法判断性能变化来自哪里。

## 8. 参数筛选顺序

按下面顺序逐项扫描，每次只改变一个参数：

1. `retinex_gain`：`16, 24, 32, 40`；观察暗部可见性和高光饱和比例；
2. `retinex_bias`：`112, 128, 144`；观察整体亮度；
3. `clahe_clip_limit`：`1.0, 2.0, 3.0, 4.0`；观察字符边缘和噪声放大；
4. 固定最优参数后，再比较 float 与 fixed 的误差。

最终参数不能只凭肉眼选择，要同时记录：平均亮度、标准差、饱和像素比例、局部对比度、运行时间，以及有参考图时的 PSNR/SSIM。

## 9. 必做的验证

### 9.1 数值验证

- `pytest` 全部通过；
- RGB→Y 使用 `77/150/29` 整数系数；
- log LUT 单调；
- float/fixed 的 MSR 平均绝对误差低于预先设定阈值；
- CLAHE 输出始终为 8 bit，尺寸不变。

### 9.2 图像验证

每类场景至少选 10 张，形成前后对照表：

| 场景 | 输入平均亮度 | 输出平均亮度 | 输入局部对比度 | 输出局部对比度 | 饱和率 | 备注 |
|---|---:|---:|---:|---:|---:|---|
| 夜间 | | | | | | |
| 逆光 | | | | | | |
| 车灯炫光 | | | | | | |

不能把“增强后更亮”直接等同于“效果更好”；车牌字符边缘、车灯附近噪声和局部过曝必须单独观察。

### 9.3 定点验证

把 `fixed` 模式输出作为后续 RTL 的第一版 golden：

1. 固定一张 320×192 测试图；
2. 导出 `input_y`、每个尺度的 `blurred_u8`、`msr_u8`、`clahe_u8`；
3. 后续 Verilog 每一级都与这些数组比对；
4. 若出现误差，先定位 RGB/Y、Gaussian、log、MSR mix、histogram、CDF、interpolation 中的具体一级。

用下面的命令导出包含各尺度 Gaussian、MSR 和 CLAHE 结果的压缩测试向量：

```powershell
cd D:\ziguang\module1_enhancement
.\.venv\Scripts\python.exe .\tools\export_golden.py `
  --demo `
  --output-dir .\golden\module1_v1
```

真实图片只需将 `--demo` 替换为 `--input D:\path\to\frame.jpg`。`golden` 目录默认被 `.gitignore` 忽略；确定参数版本后，再把需要提交的向量单独复制到版本化的测试数据目录。

## 10. 本阶段完成标准

满足以下条件后，模块一才进入 RTL 设计：

- PC 上 float 和 fixed 两种模式都能一键运行；
- 真实夜间/逆光/车灯数据都有输出和参数记录；
- CLAHE 没有明显块效应；
- fixed 模式误差阈值已确定；
- `rtl_contract.md` 中的边界、Q 格式、clip 规则和插值规则没有未决项；
- 已生成一组可版本化的 golden 测试向量。

## 11. 不允许提前做的事情

- 不在还没确定 fixed 行为时直接手写 Verilog；
- 不把 OpenCV 的黑盒结果直接当 RTL 目标；
- 不用 PSNR/SSIM 代替车牌识别准确率；
- 不在没有真实参考图时伪造“增强前后 PSNR/SSIM”；
- 不把 MSR 的浮点大卷积核原样搬进 FPGA；
- 不把项目概述中的“MSR+CLAHE”偷换成只做全局直方图均衡。
