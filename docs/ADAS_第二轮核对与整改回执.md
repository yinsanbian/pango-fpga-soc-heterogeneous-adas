### A2 的机理（对方给出、我认可）
全量泄漏档系数 `(2.757, 8.191, 6.257)` → 只换锚点的"半修"档 `(2.732, 7.967, 14.749)`。
**`|s|` 的权重从 6.26 翻倍到 14.75**——因为锚点换成样本外之后，最小二乘把权重挪到了**当时仍在泄漏**的 `|s|` 上，用泄漏补回了损失掉的解释力。

> 这条对我有直接影响：**我这一轮在工程里部署的 `AE_CALIB = (2.731599, 7.966903, 14.748860)`，正是这个"半修中间态"的系数**，不是原始全量档。我此前把它当成"原始常数"来叙述，措辞不够准确。

### A3 的机理与我的错误（独立复现）
调用 `conf_calib.py` 自身的 `loso_eval()`（`conf_calib.py:102-119`，逐折 `fit` + 逐折 `predict_ae`），特征 `("abs_anchor","abs_s")`，296 帧：

```
rho = +0.3280            ← 与文档登记的 +0.328 一致
十分位第一档 n = 29      实际中位误差 = 43.9 px   ← 与文档登记的 43.9 px 一致
  构成：7 树荫窄街 24 | 2 左转+十字路口 4 | 3 路口右转 1
各档实际中位：44 15 17 15 19 15 13 27 49 108
```

**24/29，与他们的数字逐位吻合。** 各折截距 `b0` 的离散（`expm1` 后 13.27–15.91 px，第 7 折 13.27 px 偏低）使得 `|anchor|`/`|s|` 都小的第 7 折样本挤在预测值低端，`argsort` 把它们整体推到第一档。

**我上一轮的 10–14 帧是怎么来的**：我用的是**固定全量系数**排序，而 `conf_calib.py:149` 的十分位表用的是 `order = np.argsort(all_pred)`，`all_pred` 是**逐折系数**拼出来的。两种排序不是一回事。**指控不成立，撤回。**

## 二、这一轮实际改了什么

| 文件 | 改动 | 理由 |
|---|---|---|
| `tools/lane_train.py:81` 起 | 注释从"锚点分 `N_BINS` 箱做 softmax、取期望解码"改为"**直接回归（Smooth-L1）**，不分箱不过 softmax"，并写明 V2 的 64 箱版本实测 47.2 px 更差、故放弃 | `OUT_DIM = 4` 就在同一屏内，注释与代码**自相矛盾**，读的人会以为 V3 还是分类头 |
| `tools/lane_train.py` import 段 | 删掉 `decode_anchor` / `u_to_soft_target` / `shape_basis` 三个**只 import 从不调用**的符号，以及 `N_BINS` / `U_LO` / `U_HI` 别名 | 同上；死 import 会让"V3 是分类头"的误读显得有据 |
| `tools/lane_predict.py:172` 起 | 注释从"输出 = **64 个锚点 logits** + 2 个形状参数 + 1 个有效性 logit"改为"输出 = **4 个标量**，全部 Smooth-L1 直接回归" | 同一处不一致，推理端也有一份 |
| `tools/conf_calib.py:76` | `FEATS` 默认从 `("abs_anchor","abs_s")` 改为 **`("abs_anchor",)`** | `\|s\|` 跨片段留一秩相关 **−0.106（反号）**，不迁移。`CANDIDATES` 仍保留含 `abs_s` 的组合供 `--compare` 复现 |
| `tools/lane_train.py` | 新增三个消融开关（见下） | 落实评审的 Step 0–3 阶梯 |
| `tools/lane_loso.py` / `tools/lane_eval.py` / `tools/lane_loo.py` | 同步新增/透传 `--causal-stack`，`predict_one(..., causal=)`，`gather_frames(..., causal=)` | **训练用什么窗口、评估就必须用什么窗口**；尺子和模型对不上，数字没有意义 |
| `tools/_lane_runs/conf_shape.json` | 旧的（10-07，**修复前的泄漏特征**）归档为 `conf_shape_LEAKY_insample_20261007.json`；用现版 `_diag_conf2.py` 以默认输出路径**重新生成** | 见下方"一个差点踩进去的陷阱" |

### 一个差点踩进去的陷阱
`conf_calib.py` 的 `--features` 默认指向 `_lane_runs/conf_shape.json`。而那份文件一直是 **10-07 生成的、修复前的泄漏特征**（`_diag_conf2.py:113` 的旧路径：用样本外 `pred_offset_px / f_px` 冒充 `anchor`）。修复之后它没有自动更新，于是：

```
拿旧的 conf_shape.json 跑 conf_calib（默认档）→ 建议抄 AE_CALIB = (2.740842, 10.102263)
                                                      ↑ 这是从泄漏特征拟合出来的，抄进去等于把 bug 又搬回来
真正该用的（conf_shape_fixed.json）           → AE_CALIB = (2.766376, 11.879325)
                                                      ↑ 与 lane_predict.py:78 当前部署值完全一致 ✓
```

处置：把旧的归档成带 `LEAKY` 字样的文件名，用现版脚本按默认路径重新生成 `conf_shape.json`，并**逐帧逐列比对**：

```
重新生成的 conf_shape.json  vs  conf_shape_fixed.json
  296 帧 × 17 列，不一致的格子数 = 0     数值列 max|diff| = 0.000e+00
  （列：frame,t,seg,human,pred,err,ae,anchor,abs_anchor,s,abs_s,q,abs_q,logit,curv_px,abs_curv_px,bend_px）
```

现在"默认路径"和"部署常数"指的是同一份特征，`conf_calib.py` 默认档的输出已经与 `lane_predict.py` 一致。

我另外把贵方引用过的那组数字**从归档文件重新拟了一遍**，确认它确实来自泄漏特征，且只差在拟合口径（贵方引用的是含 `|s|` 的二维拟合）：

| 特征来源 | 拟合维度 | 常数 | 留一 rho |
|---|---|---|---|
| 泄漏特征（归档件） | `\|anchor\|` | `(2.740842, 10.102263)` | +0.317 |
| 泄漏特征（归档件） | `\|anchor\| + \|s\|` | `(2.757428, 8.190818, 6.256572)` | +0.328 |
| **修复后特征** | `\|anchor\|` | **`(2.766376, 11.879325)`** | **+0.171** |

中间那一行就是贵方在 A2 里引用的 `2.757 / 8.191 / 6.257`——**数值对得上，来源也确认是泄漏特征**。修掉泄漏后，`|s|` 的权重从 6.257 涨到 14.749 的那个"半修态"也一并复现了。

### 新增的三个开关（`tools/lane_train.py`，`lane_loso.py` 同名同默认）

```
--causal-stack / --no-causal-stack   默认 ON。ON = 因果窗口 [fi-6,fi-3,fi]（与在线 lane_buf 一致）
                                     OFF = 中心窗口 [fi-3,fi,fi+3]（Step 0 基线）
--flip-aug                           默认 OFF。开水平翻转 (u_ref,s,q)→(−u_ref,−s,−q)
--tail-weight W                      默认 0。>0 时同时切到逐维 BETA + 1.5/3.0 几何权重（Step 3）
```

**默认值 = 当前主线定型档**，所以默认行为零变化；三个开关只增加可消融性，不偷偷改主线。
尾部重加权、逐维 `BETA`、几何权重这三件事**必须一起开一起关**——它们是评审文档 Step 3 定义的**那一个**自变量，拆开又变成多变量了。

## 三、我认可并要求自己遵守的纪律

1. **同一件事只能有一处实现**。采样窗口方向现在有 4 处（训练 / 两个在线端 / 评估），必须同步改，且由同一个开关控制。
2. **单变量原则**。涉及**输入分布、数据增广、损失函数**的改动不得捆绑提交。目前 `--flip-aug` 与 `--tail-weight` 默认关闭，就是因为它们各自的净收益都没有被单变量实验证明过——翻转只对左偏子群有效（37 帧 −35%），但第 9 折纯左弯道仍 68.3 px；尾部重加权则是拿直道 p50 换尾部幅度（22.8 → 25.6 px）。
3. **负面结论要写进文档**。剔除样本内泄漏后，基于模型自报幅度的置信度标定相关性很弱——留一 rho：只用 `|anchor|` 是 **+0.171**，加回 `|s|` 反而降到 **+0.155**——**不足以支撑任何自动门限拦截**，只保留为面板参考诊断量。
