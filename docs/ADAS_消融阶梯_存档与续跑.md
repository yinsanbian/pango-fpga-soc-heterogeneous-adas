## 三、已经能下的结论

### 1. 步骤差异小于种子抖动，这个阶梯分辨不出 Step 0 与 Step 1

- Step 0 两个种子之间：mean 差 **4.2 px**，max 差 **87 px**
- Step 0 与 Step 1 之间：mean 差 **1.7 px**

同一配置换个随机种子带来的差异，比换步骤带来的差异大。**n=2 个种子不足以判定，需要更多种子**，或者承认这几步在精度上等价。

### 2. 唯一两种子一致的方向：因果窗口的最坏情况更收敛

| | 种子 0 max | 种子 1 max |
|---|---|---|
| Step 0 中心窗口 | 344.33 | 256.95 |
| Step 1 因果窗口 | 291.88 | 253.59 |

两次都是因果窗口更小。**这是弱证据**，不足以单独下结论，但方向上与"训练窗口对齐在线推理"的直觉一致。

**修正一条我先前说错的话**：我曾按"精度收益"推销因果窗口。它其实**不是精度改进，是正确性修复**——训练时用的帧序必须和在线推理一致，否则离线数字没有意义。精度上它和基线分不出来。

## 四、踩过的两个坑（续跑前必读）

### 坑 1：两个进程写同一个输出目录

`run_ladder.ps1` 本身会顺序跑完 Step 0→1→2→3，而我后来**又手动补发了一次 Step 2**，两个进程同时写 `step2_flip\`。证据是同一个文件我先后读到两个不同的值：

```
先读到  mean 42.5 / p50 23.2 / max 291.4
后变成  mean 41.1 / p50 25.0 / max 268.8
```

**处置：`step2_flip` 整个作废**，干净版本重跑到新目录 `step2_flip_clean`（已启动，0/9 就停了，续跑时从头来）。

**教训：一个输出目录同时只能有一个写入者。** 续跑时不要重复启动同一个步骤。

### 坑 2：内存

本机 15.6 GB 内存，一个训练进程约占 2 GB。并发 3 个时可用内存掉到 **0.5 GB**，开始换页。并发上限按 **2 个** 控制。

顺带一个观察：训练时 GPU 利用率只有 **7%**，瓶颈在视频解码与取帧，CPU（i9-13980HX，24 物理核）大量闲置。**所以这个实验其实可以大幅并行，只是被内存卡住。** 如果以后要重做大规模消融，先解决取帧缓存或降分辨率，比换 GPU 有用。
