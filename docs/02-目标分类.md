## 一、四个分类维度

同一个目标会被四个维度同时标注，缺一不可：

| 维度 | 取值 | 回答什么问题 | 用途 |
|---|---|---|---|
| **A 性质** | INF / PLT / ALG / AI / SYS / DOC | 这是什么类型的工作？ | 分工（不同技能栈派给不同人） |
| **B 优先级** | P0 / P1 / P2 | 不做会怎样？ | 砍需求时的决策依据 |
| **C 时间** | 阶段一 ~ 阶段六（W1–W16） | 什么时候做？ | 排期 |
| **D 验证** | 功能验收 / 量化 KPI / 文档交付 | 怎么算做完？ | 验收，杜绝「我觉得做完了」 |

## 二、维度 A：按性质分类（6 大类）

| 代号 | 类别 | 定义 | 数量 | 关键特征 |
|---|---|---|---|---|
| **INF** | **使能类** | 环境、工具、驱动、工具链、板卡 | 5 | 前置依赖，不产出功能，但卡住一切 |
| **PLT** | **平台类** | 数据通路、总线、缓存、显示链路 | 7 | 系统的"骨架"，决定数据能不能流起来 |
| **ALG** | **算法类（预处理）** | 行缓存、灰度、滤波、夜间增强、边缘 | 7 | 纯硬件流水线，本项目**算法创新载体** |
| **AI** | **AI 加速类** | 模型训练、量化、CBAM、CNN、NMS | 8 | 技术高地，**风险最高** |
| **SYS** | **系统类** | 时序收敛、鲁棒性、性能与功耗实测 | 5 | 决定"能不能跑稳"，而非"能不能跑" |
| **DOC** | **交付类** | 文档、视频、源码、答辩 | 4 | 决定评委**看到**的是什么 |
| | | | **36** | |

### 各类别的依赖关系（关键路径）

```
INF ──▶ PLT ──▶ ALG ──▶ AI ──▶ SYS ──▶ DOC
(环境)   (骨架)   (预处理)  (识别)   (收敛)   (交付)
  │        │        │        │        ▲        ▲
  └────────┴────────┴────────┴────────┘        │
              贯穿全程持续投入：SYS（时序约束早期介入）
```

**关键结论**：这是一条**串行关键路径**，任何一环延误直接顺延交付。
因此 **PLT 类目标必须在 W3 结束前 100% 闭环**，否则后面全线崩盘。

## 七、风险目标与降级路径

> 原则（来自原方案）：**系统闭环稳定比加速比更重要。**

| 风险 | 触发条件 | 降级动作 | 决策时间 |
|---|---|---|---|
| R1 板卡未到位 | W1 末仍未拿到 | 官方借用未果则立即采购；同时用 PDS 仿真推进 RTL 开发 | W1 末 |
| R2 DDR3 带宽不达标 | 实测 < 20 Gbps | 降位宽/降分辨率；乒乓改三缓冲；优化突发长度 | W3 中 |
| R3 CLAHE 资源爆掉 | BRAM/DSP 超 80% | **退回全局直方图均衡（ALG-04）**，CLAHE 转为加分项 | W8 末 |
| R4 夜间增强效果不佳 | 无可见提升 | 保底方案兜底 + 在文档中说明算法权衡 | W8 末 |
| R5 **纯硬件 AI 不收敛** | **W12 决策点** | **降级为「纯硬件预处理 + 软核跑 AI」**；确保系统可完整演示 | **W12（硬门限）** |
| R6 时序违例 | W13 仍有负 slack | 降频运行（降帧率换余量）；插入流水级；放宽非关键约束 | W13 |
| R7 数据集不足 | 夜间样本 < 需求 | TLPD 为主 + 数据增强 + 合成夜间样本（亮度/噪声/色偏变换） | W9 |
