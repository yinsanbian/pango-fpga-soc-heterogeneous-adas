# 剪枝 / 蒸馏：背景原理（**本技能不提供可执行实现**）

> ## ⛔ 先读这段：为什么这份文档没有代码
>
> 本文件**只讲原理**。原因不是"没写"，而是**在本机实测确认不可用**：
>
> | 曾尝试的路径 | 实测结果 |
> |---|---|
> | `YOLO.prune(amount=0.5)` | ❌ ultralytics **8.4.147** 无此方法（`hasattr` 为 False） |
> | `model.distill(teacher=..., data=...)` | ❌ 同样不存在 |
> | `tp.strategy.L1Strategy()` + `tp.prune_conv` + `DG.get_pruning_plan()` | ❌ torch-pruning **1.5.3 与 1.6.0 都没有 `strategy` 子模块**——原文那套 API **在任何版本都不存在** |
> | `tp.MagnitudePruner(...)`（1.6 新高层 API） | ❌ 对 ultralytics 8.4 模型**剪枝量恒为 0**：依赖图只识别 **1/64** 个可剪组，`get_target_pruning_ratio()` 返回 `0.0`。试过 `forward_fn` 包装、`_predict_once`、`train()` 模式、`pruning_ratio_dict` 逐层指定比例——**全部 0 剪枝** |
> | `pip install torchpruner` + `StructuredPruner` | ❌ **PyPI 上没有 `torchpruner` 这个包** |
>
> 交叉验证：同一个 torch-pruning 在**普通 CNN 上工作正常**（TinyCNN 剪掉 54.5% 参数、前向通过）。
> 所以问题**不是安装坏了**，而是它与 ultralytics 8.4 的模型不兼容。
>
> **结论：不要在本项目环境里尝试剪枝，也不要升降依赖版本**（会破坏其他项目）。
> 需要压缩体积时，走本技能的**量化路线**（已实测可用），或换更小的模型档位重训。
> 逐条证据与复现方式见 `provenance.md`。

## 一、为什么生产环境只做结构化剪枝

- **非结构化剪枝**（逐个删权重）压缩率更高，但产生稀疏矩阵，TensorRT 等推理引擎无法高效执行，
  实际提速有限。
- **结构化（通道级）剪枝**：整条通道一起删，剪完仍是规整密集网络，可被主流推理后端正常加载。

## 二、通道重要性评估（两种主流判据）

1. **BN 层缩放因子 γ**：某通道 `|γ|` 长期接近 0，说明该通道几乎被抑制，可优先剪。
2. **卷积核 L1 范数**：对每个输出通道权重在 `(H, W, C_in)` 维度求绝对值之和，数值最小者为候选。

```python
# 仅示意判据本身（可直接算，不依赖剪枝库）
importance = torch.sum(torch.abs(conv.weight), dim=(1, 2, 3))
```

## 三、拓扑依赖与通道对齐（最易踩坑处）

- YOLO 有残差 / shortcut 连接，跳跃分支通道数一变，主路径**必须同步调整**，
  否则前向传播维度不匹配直接报错。
- 必须用**依赖图（DependencyGraph）**自动追踪跨层依赖；**勿单独剪 shortcut 分支**。
- **通道数对齐到硬件友好的倍数**：通用对齐 8；NVIDIA GPU 建议对齐到 **32 的倍数**，
  以充分利用张量核心。

## 四、分层渐进式策略（若在别的环境里做剪枝）

不要"一刀切"，YOLOv8 各部分敏感度不同：

| 部位 | 建议比例 | 理由 |
|---|---|---|
| backbone | 0.4 | 主干特征提取，冗余较多，可承受较高剪枝 |
| neck | 0.3 | 特征融合，中等敏感 |
| head | 0.2 | 检测头，敏感度高，少剪 |

工业经验：L1 阈值 **0.01~0.05**，整体剪枝率控制在 **20%~30%**；
**单层 ≤50%**，超过会形成信息瓶颈、精度急剧下降。

**先做敏感度分析**再定量：逐层试剪、观察 mAP 变化，再制定分层策略。

## 五、剪枝后必须微调

用真实数据微调：**学习率设为原训练的 1/10，训练 10~30 epoch** 可恢复大部分精度。

## 六、知识蒸馏（同样无现成 API）

思路：让大模型（teacher）教小模型（student），师生尽量**同系列**
（如 yolov8-l → yolov8-s），避免跨架构蒸馏损失。损失为硬损失 + 软损失：

```python
loss = 0.7 * detection_loss + 0.3 * KL_divergence(teacher_logits, student_logits)
```

> ⚠️ **权重口径存在分歧**：原文 A3/A4 用硬 0.7 / 软 0.3；原文 A2 主张软 0.7 / 硬 0.3
> （教师信息占比更高）。两种口径都有实践，落地以自身实验为准。

蒸馏要点：用现场真实数据、师生标注一致、训练 30~50 轮、学习率逐步衰减。

> ultralytics 没有 `model.distill()`，要做得自己写训练循环与 KD 损失。

## 七、效果量级参考（**他人数据，非本机实测**）

- YOLOv8n 约 40% 通道剪枝：体积约 ↓35%，推理速度约 ↑1.8 倍，mAP 约 ↓2.3 个百分点。
- 剪枝 + 量化组合，常可实现 60% 以上的端到端推理加速。

**这些数字来自原作者的硬件与数据集**，不要当作本机可复现的承诺。
